Ratchet Lab · Run 4 · gpt-oss-120b via Groq, bold prompt + crash-feedback retry, 100 gens

Error Feedback

The information-pressure idea · Inheritance of pain

Hypothesis

Run 3 demanded a fix, not less boldness. If a child that crashes gets one retry with its own actual error message fed into the prompt — "your previous child crashed with this exact error" — will that cure the death spiral without giving up the exploration boldness bought?

Setup

Identical to Run 3, plus: every new child first plays a fast smoke match against a dummy opponent before real evaluation. If it crash-forfeits, it gets exactly one retry, with the real runtime error text inserted into the mutation prompt. A corpse-streak detector and rate-limit backoff were added at the same time.

What changed

A smoke-check-then-retry loop, feeding each bot's own crash back into its own rewrite. Nothing else about the prompt or engine changed from Run 3.

What was measured

Coverage, best Elo, tool count, number of crash-triggered retries, and how the run compared against every prior arm on the same two axes (exploration and champion strength).

Coverage reached 66.7% — the best evolutionary arm run so far — with best Elo at 1066, 5 tools, and 148 total calls (48 of them crash-feedback retries). Crashes were exactly as frequent as Run 3 (about 48 caught), but the loop absorbed them instead of dying to them: corpse streaks maxed out at 4 in a row and always recovered, and the run was still discovering new archive cells at generations 96–100, right where Run 3 had flatlined at generation 51.

This run came close to beating every other arm on both axes at once — near cold-sampling exploration (66.7% vs 69.4%) and near evolved-arm champion strength (1066 vs 1070/1081), in a single configuration. Inherited-tool use also became the loudest signal in the whole system: roughly 2.84 million inherited-tool calls this run, manhattanDistance alone accounting for 2,754,344 of them.

What failed

The crash pattern turned out to be systematic, and per-child feedback only ever treats the symptom. Two errors accounted for nearly every crash: Cannot read properties of undefined (reading 'some') and lib is not defined. The model kept making the same category mistake — defining helper functions outside act() that try to close over act's own parameters (lib, state), which simply don't exist out there. Dozens of unrelated children independently made this mistake, got it corrected individually through their own retry, and then the next unrelated child made it again from scratch. Nothing was learned collectively.

Next

The tool library already inherits capability. Nothing yet inherits warnings. The obvious next step is a lessons library: aggregate the recurring crash patterns into short rules, inject them into every future mutation prompt — culturally transmitted "don't eat that plant" knowledge, the second half of what human generations actually pass down.
